ОТВЕТЫ СТУДЕНТА
====================================================================

1. Какую формулу реализует ваше приложение?

   Приложение реализует расчёт формулы:
   a * x^4 + b^(1/6) * x^3 + c * x^2 + (d * x) / f
   
   Где a, d, f - входные параметры, а b, c, x - константы.

2. Какие константы используются в формуле и их значения?

   - B = 340
   - C = 1.07
   - X = ∛3 ≈ 1.4422495703074083 (кубический корень из 3)

3. Какие диапазоны допустимых значений для входных аргументов?

   - a: [0.8; 1.17], шаг 0.01
   - d: [2; 5.13], шаг 0.01
   - f: [-12; 144], шаг 12

   Все границы включены (закрытые интервалы).

4. Какая точность вычислений используется и почему?

   Используется стандартная точность Ruby Float (IEEE 754 double precision, 64 бита).
   Это обеспечивает высокую точность вычислений (~15-17 значащих десятичных цифр)
   без необходимости эмуляции ограниченной точности.

5. Как реализована точность вычислений в Ruby?

   Ruby использует стандартную точность Float64 по умолчанию. Все арифметические
   операции выполняются с 64-битной точностью без дополнительных преобразований.
   Константы и входные данные используются напрямую без эмуляции.

6. Как выполняется валидация входных данных?

   Валидация проверяет три условия:
   - Соответствие диапазону (минимум и максимум с учётом включённости границ)
   - Соответствие заданному шагу (дискретность значений)
   
   Функция validate_input(value, range) возвращает true, если значение проходит
   все проверки.

7. Какие ошибки обрабатывает приложение?

   - Деление на ноль (f = 0)
   - Неверный формат JSON при загрузке файла
   - Отсутствие обязательных полей в JSON файле
   - Некорректные типы данных в загружаемых наборах
   - Выход за пределы допустимых диапазонов
   - Нарушение шага дискретизации

8. Как реализована загрузка тестовых наборов из файлов?

   Загрузка реализована через API endpoint POST /load-file:
   - Принимает файл в формате multipart/form-data
   - Парсит JSON и проверяет наличие массива "sets"
   - Валидирует каждый набор на наличие числовых значений a, d, f
   - Возвращает загруженные данные или ошибку валидации

9. Какие технологии и фреймворки использованы в проекте?

   - Ruby (язык программирования)
   - Sinatra (веб-фреймворк)
   - ERB (шаблонизатор для HTML)
   - Puma (веб-сервер)
   - JSON (для работы с данными)
   - MathJax (для отображения математических формул)
   - rubocop (для проверки качества кода)

10. Какова архитектура приложения?

    Приложение реализовано по архитектуре клиент-сервер:
    - Клиентская часть: HTML + JavaScript (в views/index.erb)
    - Серверная часть: Sinatra приложение (app.rb)
    - API endpoints для расчёта и загрузки файлов
    - Шаблоны ERB для рендеринга HTML

11. Какова погрешность вычислений в данной реализации?

    Погрешность обусловлена использованием стандартной Ruby Float (64 бита):
    - Точность представления: ~15-17 значащих десятичных цифр
    - Относительная погрешность: 10^-15 - 10^-16 (очень малая)
    - Источники погрешности: минимальные ошибки округления при арифметических
      операциях, возведение в дробную степень

12. Как устроен пользовательский интерфейс?

    Пользовательский интерфейс включает:
    - Форму ввода параметров a, d, f с подсказками о диапазонах
    - Кнопку расчёта
    - Секцию отображения результата с формулой в формате MathJax
    - Секцию загрузки тестовых наборов из JSON файлов
    - Таблицу для отображения результатов нескольких наборов
    - Кнопки навигации между наборами аргументов

13. Как работает API для расчёта формулы?

    API endpoint POST /calculate:
    - Принимает JSON с полями a, d, f
    - Валидирует входные данные
    - При ошибке возвращает HTTP 400 с описанием ошибок
    - При успехе возвращает JSON с входными данными и результатом расчёта

14. Как работает API для загрузки файлов?

    API endpoint POST /load-file:
    - Принимает файл через multipart/form-data
    - Парсит JSON содержимое файла
    - Проверяет структуру (наличие массива "sets")
    - Валидирует каждый набор на корректность типов
    - Возвращает загруженные данные или ошибку валидации

15. Какие преимущества у выбранной архитектуры?

    - Разделение клиентской и серверной части для лучшей масштабируемости
    - Использование REST API для чистого разделения ответственности
    - Sinatra обеспечивает простоту и скорость разработки
    - ERB позволяет использовать стандартные Ruby шаблоны
    - Клиентская валидация снижает нагрузку на сервер
    - Поддержка загрузки файлов упрощает тестирование
